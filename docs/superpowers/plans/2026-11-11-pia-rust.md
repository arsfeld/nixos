# PIA Control Plane in Rust Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the inline Python `pia` and `pia-watchdog` programs in `modules/hosts/galactica/services/pia.nix` with one Rust binary, `packages/pia`, with identical units, files and behaviour.

**Architecture:** A synchronous Rust CLI with three subcommands (`connect`, `portforward`, `watchdog`). Each subcommand is split into pure decision functions, which are unit-tested, and a thin `run` that does I/O. HTTP goes through blocking reqwest + rustls; the pinned client trusts only PIA's CA and maps the server CN to its IP with `resolve()`, which stands in for curl's `--connect-to`. `wg`, `ip`, `iptables` and `systemctl` stay subprocesses, at absolute paths passed in through the environment.

**Tech Stack:** Rust 2024, reqwest 0.12 (`blocking`, `json`, `multipart`, `rustls-tls`), serde/serde_json, base64 0.22, chrono, anyhow, clap 4; Nix `rustPlatform.buildRustPackage`.

**Spec:** `docs/superpowers/specs/2026-11-11-pia-rust-design.md`

## Global Constraints

- Commit straight to `master`, no branches or worktrees. Conventional commits, scope `galactica`. Never mention Claude.
- New files are invisible to `nix build` until `git add`ed (`git add -N` is enough).
- File contract, unchanged: `/var/lib/pia/state.json` mode 0600; `/run/pia/wg0.conf` 0600; `/run/pia/forwarded-port` 0644 holding `<port>\n`; `/run/pia` 0755; `/var/lib/pia` 0700. Writes are atomic: `<path>.tmp`, chmod, rename.
- `state.json` field names are unchanged: `token`, `pf_gateway`, `pf_hostname`, `dns_servers`, `payload`, `signature`, `expires_at`, `port`, `applied_port`. Unknown fields round-trip.
- Timeouts: `getSignature` and `bindPort` take 10 s; `token`, the server list and `addKey` take 30 s.
- Never log or put in an error: the password, token, payload, signature or private key, or any request URL with its query. Use `reqwest::Error::without_url()`.
- Signature renewal margin is 86 400 s. Watchdog staleness and grace are both 300 s.
- Environment variables read by the binary: `PIA_CREDENTIALS`, `PIA_REGION`, `PIA_CA_CERT`, `PIA_NAMESPACE`, `PIA_HOOK`, `PIA_WG`, `PIA_IP`, `PIA_IPTABLES`, `PIA_SYSTEMCTL`. The tunnel interface is `<namespace>0`.
- Log prefixes: `pia: ` (connect, portforward), `pia-watchdog: ` (watchdog). Errors exit 1.
- Tests run from `packages/pia` with `cargo test`. Each task ends with `cargo test` green and `cargo clippy --all-targets -- -D warnings` clean.
- Out of scope: a daemon, in-process key generation, netlink.

## Review Focus

1. **The live `state.json` written by the Python version.** `port`/`applied_port` are JSON integers, `applied_port` may be absent, and `expires_at` is PIA's RFC 3339 timestamp with nanoseconds and `Z`. It must load, and a renewal must not be forced. Pinned in Task 3 (`loads_python_written_state`) and Task 6 (`nanosecond_expiry_is_valid`).
2. **Secrets leaking through reqwest error text.** `reqwest::Error`'s Display includes the URL, which holds `token=`/`payload=`/`signature=`. Pinned in Task 4 (`transport_error_hides_query`).
3. **A failing consumer hook.** The port file and the iptables rule must already be in place, and `applied_port` must stay unchanged so the next run retries. Pinned in Task 6 (`hook_failure_keeps_applied_port`).
4. **A password containing `=` or `#`.** Split once on the first `=`; a `#` that is not at the start of the line is part of the value. Pinned in Task 2 (`password_with_equals_and_hash`).
5. **A region whose `servers.wg` is empty or missing.** It must be an error naming the region, not a panic. Pinned in Task 5 (`region_without_wg_servers_errors`).
